# 逐课维护约定

## 每节课的交付

1. 核对官网主题、源码实际目录和上游提交，记录差异。
2. 只把当前课的新源码及所需依赖加入公开参考仓库，保留原作者许可与来源。
3. 原版源码和教学讲解分开；确实需要兼容性修改时，单独说明差异并提交。
4. 先讲本节目标，再按小步骤指导学生在私有仓库手敲；收到学生结果后核对。
5. 验证本课关键行为；区分无网络检查和真实 API 运行。
6. 以 `feat(sXX): ...` 提交参考实现，建立 `lesson-sXX` 标签。
7. 更新本机学习档案，记录学生实际完成、尚未完成及下一步。

## 仓库边界

- 助手可以维护 `learn-agent-reference`。
- `learn-agent-practice` 的课程代码、Git 提交和 push 由学生亲手完成。除非学生明确改变这一约定，不代写、不代提交。
- 学生的错误日志、个人基础、密钥和本机学习进度不发布到公开参考仓库。
- 不提交 `.env`、虚拟环境或真实 API Key；固定依赖和 `.env.example` 可以提交。
- 一课结束以学生能运行、能解释、能上传为准；仅创建参考仓库不算学完。

## 每课验收

学生能用自己的话说明本课新增机制；能运行一个小例子；能解释关键消息与工具调用；能独立查看 `git status`、完成 commit 和 push，并在 GitHub 找到相应提交。
