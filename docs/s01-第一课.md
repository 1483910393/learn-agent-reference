## 1. 先分清三个位置

| 名称 | 是什么 | 本课用途 |
| --- | --- | --- |
| 本地文件夹 | 你电脑上的代码文件 | 在 VS Code 里敲代码、运行 |

练习仓库创建时保持为空，目的是让你从 `git init` 开始完成第一次提交。

## 6. 创建虚拟环境并安装依赖

虚拟环境是这个项目专用的一套 Python 运行环境。它让本项目安装的库与其他项目分开。

在练习目录的终端输入：

```powershell
uv venv --python 3.13 .venv
```

然后新建 `requirements.txt`，敲入上游的依赖要求：

```text
anthropic>=0.25.0
python-dotenv>=1.0.0
pyyaml>=6.0
```

其中 `anthropic` 负责请求 Claude API，`python-dotenv` 读取 `.env`；`pyyaml` 为后续课时预留，s01 暂时没有使用。

执行：

```powershell
uv pip install --python .venv/Scripts/python.exe -r requirements.txt
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -c "import anthropic, dotenv; print('imports OK')"
```

应看到 `imports OK`。`-r` 表示从依赖列表安装，`--python` 指定装进哪个 Python 环境。

如果要与参考仓库使用完全相同的版本，可以改用：

```powershell
uv pip install --python .venv/Scripts/python.exe -r ..\learn-agent-reference\requirements.lock.txt
```

VS Code 按 `Ctrl+Shift+P`，输入 `Python: Select Interpreter`，选本项目 `.venv\Scripts\python.exe`。若命令不存在，先到扩展面板安装 Microsoft 发布的 Python 扩展。

本教程通过完整的 `.venv` 路径运行，不要求激活环境，也不需要修改 PowerShell 执行策略。

## 7. 配置你已有的 Claude API Key

先新建 `.env.example`，敲入：

```dotenv
ANTHROPIC_API_KEY=replace-with-your-own-key
MODEL_ID=claude-sonnet-4-6
```

这是配置模板，里面只放占位符。然后执行：

```powershell
Copy-Item .env.example .env
code .env
```

在本机打开的 `.env` 中，将占位符替换成你自己的真实 API Key，保存。不要在 `.env.example` 中填真实密钥。

这里的 `MODEL_ID` 沿用上游示例；若你的 Anthropic 控制台不提供这个模型，请使用账号实际可用的模型 ID。先不配置 `ANTHROPIC_BASE_URL`，官方 Anthropic Key 走 SDK 的默认地址。

检查配置是否可读，同时不打印密钥：

```powershell
.\.venv\Scripts\python.exe -c "import os; from dotenv import load_dotenv; load_dotenv(override=True); k=os.getenv('ANTHROPIC_API_KEY',''); print('key configured:', bool(k) and k != 'replace-with-your-own-key'); print('model:', os.getenv('MODEL_ID','MISSING'))"
git check-ignore .env .venv/Scripts/python.exe
```

应显示 `key configured: True`、模型名称，以及被忽略的两个路径。此检查只说明配置被读到，不能验证 Key 是否有效、是否有余额。

API 调用按 Anthropic 账户计费，与聊天订阅分开。后续遇到 401、403、429 时，需要分别排查密钥、权限、余额或限流。

## 9. 第一次运行

在练习仓库根目录执行：

```powershell
New-Item -ItemType Directory -Path sandbox -Force
Set-Location sandbox
..\.venv\Scripts\python.exe ..\s01_agent_loop\code.py
```

此时应出现 `s01: Agent Loop` 和输入提示。程序会从脚本的目录向上找到项目 `.env`。`sandbox` 只是我们取的文件夹名，不能阻止程序访问外部文件。

先输入：

```text
只回复“你好”，不要调用工具。
```

再输入：

```text
请调用工具列出当前目录的文件，使用 Windows cmd 命令，然后告诉我结果。
```

模型通常会请求 `dir`。终端会先显示命令和输出，再显示最终回答。
工具名虽然叫 `bash`，但这份源码在 Windows 上通过 `subprocess.run(..., shell=True)` 使用 `cmd.exe`，因此 `dir`、`type` 等 Windows 命令才是本课的合适例子。

第三次可输入：

```text
在当前目录创建 hello.py，让它打印 Hello, World!，然后运行它。运行 Python 时用 py -3.13。
```

观察 `hello.py` 是否出现在 `sandbox`。模型可能调用一次工具，也可能分几次；观察“命令 → 结果 → 下一次请求”。如果没有创建文件或模型报错，保留经过脱敏的终端信息，先排错。

输入 `q` 退出，再回到仓库根目录：

```powershell
Set-Location ..
```

## 12. 创建第一次本地提交

先看当前状态：

```powershell

```

应该看到待跟踪的代码、README、依赖、模板、许可和 `.gitignore`，不应该看到 `.env` 或 `.venv`。

分两步把明确的文件放进暂存区，再查看：

```powershell

git status
```

- `git add` 选择“这次快照包含哪些文件”。
- `--cached` 看的是已经暂存、下一次准备提交的内容。
- 如果进入分页查看器，按 `q` 退出。
- 核实差异中没有真实密钥，再提交：

```powershell
git commit -m "feat(s01): implement agent loop by hand"
git log --oneline -1
```

输出会包含一个短提交编号和提交说明。到这里代码还只在你的电脑里。

## 13. 连接并上传到 GitHub

私有练习仓库已由助手创建，不用在网页重复创建，也不要初始化网页 README。

```powershell
git remote add origin https://github.com/1483910393/learn-agent-practice.git
git remote -v
git push -u origin main
```

- `origin` 是给远程仓库起的本地简称。
- `push` 上传本地提交。
- `-u` 记住本地 `main` 对应远程 `origin/main`，以后通常只需 `git push`。

若系统提示登录，使用 Git Credential Manager 的浏览器流程；不要把 GitHub 网站密码当作 Git 密码输入。

遇到 `remote origin already exists`，先运行 `git remote -v` 核对，不要再添加。若地址就是练习仓库，继续 push 即可。遇到 `src refspec main does not match any`，检查是否已经 commit，以及 `git branch --show-current` 是否是 `main`。

如果提示 `non-fast-forward`，不要强推，先把当前状态和错误文字发给助手；远程可能已有你之后创建的文件。


## 16. 常见错误

| 现象 | 先检查什么 |
| --- | --- |
| 提示符变成 `>>`，后续输入没有输出 | 引号或括号可能没有闭合；按 `Ctrl+C` 取消，检查完整命令后逐行重输 |
| 中文说明被报为 `CommandNotFoundException` | 终端只输入代码框中的命令；解释文字在聊天中阅读 |
| `Set-Loction` 无法识别 | 正确拼写是 `Set-Location`，中间含有字母 `a` |
| `ModuleNotFoundError: anthropic` | 是否用当前项目 `.venv` 的 Python 运行；依赖是否装在这里 |
| `KeyError: MODEL_ID` | `.env` 是否叫这个名字而非 `.env.txt`，是否填写并保存 `MODEL_ID` |
| 提示缺少 API Key | `.env` 是否位于仓库根目录；密钥变量是否拼对 |
| 401 | Key 是否有效、是否有多余空格、是否用错平台 |
| 403 / 404 | 账号权限、模型 ID、官方接口地址与账号可用模型 |
| 429 | 限流、余额或账号用量限制，查看平台错误详情 |
| 连接超时 | 本机网络、代理及 Anthropic 服务连通性 |
| `python` 无输出或打开商店 | 改用 `py -3.13` 或 `.venv` 的明确路径 |
| `cat` / `ls` 无法识别 | 当前工具实际运行在 Windows cmd，换用 `type` / `dir` |
| `fatal: not a git repository` | 当前目录是不是 `learn-agent-practice` 或其子目录 |

分享错误时保留报错类型与上下文，去掉 API Key、Token 和其他敏感配置。
