# 第一课：分块手敲 s01 源码

配合 [环境与 GitHub 操作教程](s01-第一课.md) 使用。下面六段按顺序放进你自己的 `s01_agent_loop/code.py`；每段之间空两行即可。源码来自固定版本的 ShareAI 项目，保持原样，解释放在代码块外。

你在终端用 PowerShell 操作；程序内部的 `bash` 工具在 Windows 上实际通过 cmd 执行命令。这是两个不同的 shell 环境。

先理解一次完整旅程：

```text
你的输入 → history → Claude API
                       ↓
                 有 tool_use？
                 ↓是         ↓否
            Python 执行命令   返回最终回答
                 ↓
       tool_result 放进 history
                 ↓
              再请求 Claude
```

模型决定要做什么；Python 负责真正调用工具和传递结果。你在学习构建这个运行框架，不是在训练一个模型。

## 1. 文件说明与导入

最上面的三引号是文件说明，不会调用 API。`os` 读取环境变量、识别系统和获取当前目录；`subprocess` 运行外部命令。

`readline` 改善终端输入体验，Windows 标准环境可能没有它，所以通过 `try/except ImportError` 忽略；`pass` 表示什么也不做。`Anthropic` 是 API 客户端类，`load_dotenv` 是读取配置的函数。

敲代码时注意：`from`、`import`、模块名是不同部分；Python 用缩进表示代码层级，统一四个空格。

```python
#!/usr/bin/env python3
"""
s01_agent_loop.py - The Agent Loop

The entire secret of an AI coding agent in one pattern:

    while True:
        response = LLM(messages, tools)
        if response contains no tool_use:
            break
        execute tools
        append results

    +----------+      +-------+      +---------+
    |   User   | ---> |  LLM  | ---> |  Tool   |
    |  prompt  |      |       |      | execute |
    +----------+      +---+---+      +----+----+
                          ^               |
                          |   tool_result |
                          +---------------+
                          (loop continues)

This is the core loop: feed tool results back to the model
until the model decides to stop. Later chapters add policy,
hooks, and lifecycle controls around it.

Usage:
    pip install anthropic python-dotenv
    ANTHROPIC_API_KEY=... python s01_agent_loop/code.py
"""

import os
import subprocess

try:
    import readline
    # #143 UTF-8 backspace fix for macOS libedit
    readline.parse_and_bind('set bind-tty-special-chars off')
    readline.parse_and_bind('set input-meta on')
    readline.parse_and_bind('set output-meta on')
    readline.parse_and_bind('set convert-meta off')
except ImportError:
    pass

from anthropic import Anthropic
from dotenv import load_dotenv
```

## 2. 读取配置，建立客户端和系统提示词

`load_dotenv(override=True)` 从 `.env` 读取配置；`override=True` 表示同名变量以 `.env` 为准。`os.getenv(...)` 在变量不存在时返回 `None`，而 `os.environ["MODEL_ID"]` 缺少变量会报 `KeyError`。

配置自定义 `ANTHROPIC_BASE_URL` 时移除可能冲突的 `ANTHROPIC_AUTH_TOKEN`；本课使用官方 Key，通常不需要填写 BASE_URL。创建 `client` 对象并不会立刻发送模型请求。

`os.name == "nt"` 表示 Windows。条件表达式 `A if 条件 else B` 选择对应说明。`f"...{表达式}..."` 是把表达式结果填进字符串的写法。

`SYSTEM` 告诉模型它所在的目录、命令环境和任务风格。`os.getcwd()` 返回的是你启动程序时的当前目录，因此教程先进入 `sandbox` 再启动。

```python
load_dotenv(override=True)

if os.getenv("ANTHROPIC_BASE_URL"):
    os.environ.pop("ANTHROPIC_AUTH_TOKEN", None)

client = Anthropic(base_url=os.getenv("ANTHROPIC_BASE_URL"))
MODEL = os.environ["MODEL_ID"]

ENVIRONMENT_PROMPT = (
    "Windows: the bash tool runs through cmd.exe; use cmd.exe syntax, not Unix "
    "Bash or PowerShell syntax"
    if os.name == "nt"
    else "Unix-like: the bash tool runs the system shell"
)
SYSTEM = (
    f"You are a coding agent at {os.getcwd()}. Environment: {ENVIRONMENT_PROMPT}. "
    "Use bash to solve tasks. Act, don't explain."
)
```

## 3. 向模型声明工具

`TOOLS` 是列表，里面放一个字典。字典通过键值对描述工具名称、作用和参数格式。

`input_schema` 是 JSON Schema：这里要求输入是对象，有一个字符串属性 `command`，而且必须提供它。它告诉模型怎样提出工具请求，本身不会执行命令。

工具叫 `bash` 是课程中的名称；不能由名称推断 Windows 上运行的是 Unix Bash。

```python
# -- Tool definition: just bash --
TOOLS = [{
    "name": "bash",
    "description": "Run a shell command.",
    "input_schema": {
        "type": "object",
        "properties": {"command": {"type": "string"}},
        "required": ["command"],
    },
}]
```

## 4. 真正执行命令

函数定义里的 `command: str` 和 `-> str` 是类型提示：期望收到字符串，并返回字符串。它们不会自动验证所有输入。

`any(...)` 检查有没有命中简单拒绝词；这只是教学示意，不能覆盖命令变体，也不能当完整权限系统。`subprocess.run` 才是真正执行命令的位置。

`shell=True` 使用系统 shell；Windows 上是 cmd。`cwd` 指定命令的工作目录，`capture_output=True` 收集输出，`text=True` 按文本处理，`timeout=120` 最多等待 120 秒。`errors="replace"` 避免某些解码错误直接中断程序。

`stdout` 是标准输出，`stderr` 是错误输出；合并后去掉首尾空白，最多返回 50000 个字符。`out[:50000]` 是字符串切片。超时或系统错误被转成文字结果，供模型下一轮看到。

```python
# -- Tool execution --
def run_bash(command: str) -> str:
    dangerous = ["rm -rf /", "sudo", "shutdown", "reboot", "> /dev/"]
    if any(d in command for d in dangerous):
        return "Error: Dangerous command blocked"
    try:
        r = subprocess.run(command, shell=True, cwd=os.getcwd(),
                           capture_output=True, text=True, errors="replace", timeout=120)
        out = (r.stdout + r.stderr).strip()
        return out[:50000] if out else "(no output)"
    except subprocess.TimeoutExpired:
        return "Error: Timeout (120s)"
    except (FileNotFoundError, OSError) as e:
        return f"Error: {e}"
```

## 5. 核心 Agent Loop

这是本课的重点。先敲一遍，再从上到下解释执行顺序：

1. `while True` 启动内层循环；每一圈请求一次模型。
2. `client.messages.create` 才会发出网络请求；`model` 是模型 ID，`system` 是系统提示，`messages` 是历史，`tools` 是可调用工具声明，`max_tokens` 限制一次响应的输出预算。
3. 先保存模型的完整响应。`response.content` 是内容块列表，可能同时有文字和工具调用。
4. 列表推导式筛出 `type == "tool_use"` 的块。没有工具调用时 `return`，退出本次任务的内层循环。
5. 对每个工具块，读出模型给的 `command`，调用我们写的 `run_bash`。
6. 为每次调用构造 `tool_result`。`tool_use_id` 必须与原调用的 `block.id` 一致，用来对应“哪一个调用产生了这个结果”。
7. 结果以 `role: "user"` 追加到历史，这是 Anthropic 的工具消息格式，不表示你真的又手动输入了一条消息。
8. 回到循环顶部。下一次请求包含刚才的调用与结果，模型据此决定继续操作还是回答。

终端只显示工具结果的前 200 个字符，传给模型的 `output` 则来自 `run_bash`，最多 50000 个字符。

`messages` 是可变列表，函数里的 `append` 会改变外面传进来的 `history`；因此调用函数后，入口代码还能读到最后的模型回答。这里没有另行返回历史列表。

官网正文的旧示例使用 `stop_reason`；当前固定源码检查真实内容块。手敲时以这里为准，不把两个版本混在一起。

```python
# -- The core pattern: a while loop that calls tools until the model stops --
def agent_loop(messages: list):
    while True:
        response = client.messages.create(
            model=MODEL, system=SYSTEM, messages=messages,
            tools=TOOLS, max_tokens=8000,
        )

        # Append assistant turn
        messages.append({"role": "assistant", "content": response.content})

        # If the model didn't call a tool, we're done
        tool_calls = [
            block for block in response.content if block.type == "tool_use"
        ]
        if not tool_calls:
            return

        # Execute each tool call, collect results
        results = []
        for block in tool_calls:
            print(f"\033[33m$ {block.input['command']}\033[0m")
            output = run_bash(block.input["command"])
            print(output[:200])
            results.append({
                "type": "tool_result",
                "tool_use_id": block.id,
                "content": output,
            })

        # Feed tool results back, loop continues
        messages.append({"role": "user", "content": results})
```

## 6. 交互入口

`if __name__ == "__main__":` 表示这个文件被直接运行时，才进入终端交互部分。

这个外层 `while True` 等待你不断输入新问题；前面的内层循环则完成“一道问题所需的多次模型与工具往返”。要区分它们。

`history` 在外层循环之前创建，所以程序没有退出时会保留多轮对话；退出后历史不会自动保存到磁盘。输入 `q`、`exit` 或空白会退出，`Ctrl+C` 也会结束等待输入。

`` 等转义是终端颜色控制；``、`` 是给 Readline 的宽度标记。少数终端可能显示小符号，不影响核心循环，先不要因此改写原源码。

`history[-1]` 读取最后一条消息。最后只打印类型为 `text` 的内容块，不把工具调用对象当成最终答案。`getattr(block, "type", None)` 是安全读取对象属性，缺少时返回 `None`。

```python
# -- Entry point --
if __name__ == "__main__":
    print("s01: Agent Loop")
    print("Enter a question, press Enter to send. Type q to quit.\n")

    history = []
    while True:
        try:
            # \001/\002 tell Readline the ANSI escapes have zero display width.
            query = input("\001\033[36m\002s01 >> \001\033[0m\002")
        except (EOFError, KeyboardInterrupt):
            break
        if query.strip().lower() in ("q", "exit", ""):
            break
        history.append({"role": "user", "content": query})
        agent_loop(history)
        # Print the model's final text response
        response_content = history[-1]["content"]
        if isinstance(response_content, list):
            for block in response_content:
                if getattr(block, "type", None) == "text":
                    print(block.text)
        print()
```
